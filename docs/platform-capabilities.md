## 能力来源

backend/app/services/platforms/catalog.json 是统一目录。assignments 和 learning 使用明确布尔值，未知平台和未知业务默认关闭。course_selection 表示作业中的课堂选择，不表示支持视频网课。

后端通过 GET /api/accounts 返回能力，前端平台目录直接复用同一份 JSON。desktop/src/lib/platforms.js 统一完成账号过滤、业务默认账号选择与记录归属过滤。服务端明确禁用的能力不会因为前端目录存在而被放开。

## 页面与流程

- 平台页显示每个平台的作业、网课标记；已授权账号只提供支持业务的跳转入口。
- 作业页只显示支持作业的账号，一键采集采用同一范围。
- 网课页只显示支持网课的账号。当前账号不适用时，选择有效的业务账号；没有有效账号时提供平台管理入口并禁用采集。
- 切换账号时清空课程、当前任务、事件和截图；旧请求的结果不能覆盖新账号。
- 同名账号使用本地账号 ID 关联，不能靠姓名合并课程或任务。
- 账号列表定期刷新不会清空当前有效课程选择。
- 作业自动检测配置只包含支持作业的账号。

## 接口边界

学习通课程中心可能默认显示“我教的课”。作业和网课采集通过共享入口选择“我学的课”，确认列表响应完成后再解析课程。已处于学生视角时不重复加载，旧版无角色标签的学生课程页保持兼容。年份筛选只采用明确的开课日期，不根据课程名称或账号年级猜测。

后端 require_business 使用同一目录进行校验。能力不符时返回 HTTP 409 和业务说明，不返回其他账号的列表，也不把它伪装为空结果。

网课的课程列表、账号执行记录、采集、课程导入、任务创建与重试均校验能力。作业与学期的按账号查询、作业采集及任务启动同样校验能力。

平台历史任务不会因为能力变化而被删除。具体历史记录仍可查看，停止与资源清理保留；不支持的业务不能借历史记录重新启动。

头歌课堂使用 /api/accounts/{account_id}/courses，属于课堂实验作业；/api/learning/courses 属于网课。前者正常可用不意味着后者应该允许访问。

## 验证

测试覆盖能力矩阵、未知能力、服务端禁用、无适用账号、同名账号归属、头歌拒绝网课操作、网课平台导入、历史记录保留，以及网课专属账号拒绝作业操作。

实际电脑端界面已验证头歌仅显示作业入口、网课下拉框排除头歌，以及学习通两个账号间课程和历史结果切换。没有触发课程执行或作业评测。

新增平台时先实现适配器，再修改目录中的能力标记并补相应测试；不通过硬编码名称在某个页面单独放开能力。
