# 签到功能

## 1. 当前范围

左侧“签到”提供多账号活动采集、批次执行、逐账号结果、二维码图片读取和批量分享。首版支持学习通，平台能力字段为 attendance。头歌和其他平台不会出现在签到账号列表中。

活动列表的 status=1 只用于发现候选活动。采集还逐项核对签到详情的结束标记、起止时间，以及当前账号的个人出勤状态；只有当前处于有效时段且个人状态为未签到的记录才进入列表。时间按 Asia/Shanghai 处理，支持秒、毫秒、平台日期对象和带时区时间。有效区间为“开始时间 ≤ 当前时间 < 结束时间”。

没有结束时间的记录不会默认视为永久有效，只有平台明确确认不限时且尚未结束时才可展示。已结束、尚未开始、已签到或时间无法核实的记录不作为可签到项目展示。页面显示完整起止日期，到期后自动移除记录和勾选；创建批次与实际提交前也会再次验证时段。

| 方式 | 首版行为 |
| --- | --- |
| 普通签到 | 核验账号、课程归属、活动状态和个人出勤后提交 |
| 签到码、手势码 | 使用用户提供的码，先做平台校验，再提交 |
| 二维码 | 粘贴有效二维码链接或导入图片；二维码必须对应当前活动 |
| 位置签到 | 提供浏览器定位或手动填写经纬度及地点；缺失时保留为“待补充”，补充后继续，由平台核验位置 |
| 照片、人脸、额外验证码、设备校验 | 显示“需本人处理”，通过该账号的浏览器进入平台；处理后重新核对 |

活动读取与签到使用 Playwright 的 APIRequestContext，读取本软件已保存的 storage_state。采集和批量提交不启动 Chrome 窗口，不另存账号密码，也不修改原始授权文件。只有点击“打开签到”时才使用现有的交互浏览器入口。

## 2. 使用流程

1. 在“平台”完成学习通授权。
2. 打开“签到”，勾选账号，点击“采集签到”。
3. 根据课程、账号、方式选择活动。右侧可填写签到码或导入二维码图片。选择位置签到后，可获取当前位置或手动填写位置。分享页面同样支持填写位置。
4. 点击“批量签到”，查看逐账号回执。缺少信息时补充后点击“继续执行”，已有成功回执的项目不会重交。
5. 需要由其他人提供签到信息时，点击“分享签到”，创建当前勾选范围的批次与分享链接。已有批次也可通过右侧分享按钮创建链接。
6. 平台处理完成或结果不明确时，点击“核对签到结果”。

每个批次最多 100 项。默认并发上限为 3，同一账号、同一活动分别串行，多个批次重叠选择相同活动时也不会同时提交。某一账号失败不会中止其他账号。

## 3. 分享服务

管理 API 默认仍使用 127.0.0.1:8877。创建分享时，应用启动独立的分享监听端口，默认 8878；这个服务只提供分享页面、二维码解码脚本、受限状态查询和受限执行接口。管理账号、作业、网课等接口不会挂载到分享服务。

- 默认链接用于同一局域网，电脑需要保持应用运行，系统需要允许分享端口访问。
- 跨网络使用时，将自有 HTTPS 域名反向代理到分享端口，并在创建链接时填写该域名；管理端口不需要对外开放。
- 有效期为 5、15、30 或 60 分钟。后端同时验证有效期，最大 60 分钟。
- 分享仅授权当前批次，页面没有选择其他账号、创建其他批次或获取登录态的接口。姓名只显示首字。
- 分享凭据保存在 URL 片段中，HTTP URL 不携带它；浏览器通过 Authorization 请求头使用凭据。数据库仅保存摘要。
- 所有人共享该批次的执行进度。停止批次会撤销其分享；也可单独撤销某个链接。过期或撤销会阻止尚未发出的操作，已经送达平台的签到需要按实际回执核对。
- 应用重启后，可恢复尚未到期的分享监听；此前未确认的提交仍需核对。

分享页面和工作区均在本地解码图片。二维码图片不上传到外部识别服务。

## 4. 状态与维护

| 状态 | 含义与下一步 |
| --- | --- |
| pending、queued | 待执行、排队中 |
| running | 核验账号、活动、个人出勤和必要输入 |
| submitting | 请求即将或已经送达，等待平台回执 |
| succeeded、already_signed | 有明确成功回执，或平台已经显示签到成功 |
| awaiting_input | 缺少位置、二维码、签到码，或输入未通过校验；补充后继续 |
| manual_required | 需要在学习通本人处理；处理后核对 |
| auth_required | 授权失效；更新授权后继续或核对 |
| expired | 平台签到活动已结束，不再提交 |
| failed | 提交前检查失败，或平台明确拒绝；核对原因后重试 |
| unknown | 提交可能已经送达，但没有明确回执；只允许先核对，阻止直接重试 |
| cancelled | 尚未发出的操作已经取消；可由本机用户继续 |

成功必须来自明确的平台回执，不能用包含“成功”的字符串片段判断。请假、缺勤等其他出勤状态也不会被当作签到成功。提交网络请求的自动重试次数为 0。

数据表位于现有 SQLite：attendance_activities、attendance_batches、attendance_items 和 attendance_shares。采集失败的课程保留上次记录并报告失败；确认不再属于当前账号的课程会从活动列表移除。应用退出或重启时，已进入 submitting 的记录保守转为 unknown。

旧版未保存截止时间或核验结果的缓存迁移后先标记为 unverified，不再直接展示；重新采集通过后恢复。核验失败课程的缓存同样暂停展示，历史批次与结果保留。列表查询会按当前时间过滤缓存，并排除已有成功回执、正在执行或待核对的活动，旧勾选不能绕过后端检查。

日志沿用系统已有 main.log / oldmain.log 机制，按 attendance.collection、attendance.preflight、attendance.submitting、attendance.result 和 attendance.error 等事件检索。batch_id、item_id、account_id、activity_id 用于追溯；前台显示简短原因，完整异常链进入日志。日志不主动保存签到码、二维码或分享凭据。

## 7. 四种签到实测

2026 年 11 月 13 日，在用户专门发布的“计算机科学”测试活动中，使用 2 个已授权测试账号执行批量签到。签到码、手势码、二维码和位置共 8 项均收到成功回执，随后独立查询个人出勤接口，8 项状态均为已签到。

位置测试活动未设置地点及范围，测试提交使用明确标注“功能联调测试位置（非实际定位）”的模拟坐标。因此，这次结果只证明位置输入、提交和回执流程可用，不证明真实定位精度或范围限制校验已通过实测。正式使用时应提供对应账号的实际位置；人脸、照片和设备校验仍由本人处理。

首次实测发现活动解析继承了本地批次行的 status 字段，将进行中的活动误判为过期。解析已改为只继承课程标识、班级标识及课程名称，并增加回归测试。错误尝试保留在历史批次中；该次在提交前被拒绝，没有发出签到请求。

隔离浏览器测试覆盖缺少位置、无效坐标、模拟浏览器定位、补充后继续、成功项目不重复提交，以及分享页面的同步与撤销。模拟测试使用独立临时数据库，不写入真实出勤记录。
