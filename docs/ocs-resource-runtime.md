# OCS 资源流程补全与错误处理

日期：2026 年 11 月 12 日。引擎标识：ocs-5.4.0-resources.2。

## 本次真实问题

“形势与政策Ⅴ”卡在同一章节。现场日志表明：视频已由平台标记完成；另有一个 PPT 文档仍未完成。旧执行器虽然发现阅读页面，却只把音视频放进执行循环，因此反复等待人工，继续之后仍然找不到播放任务点。

旧进程也尚未加载上一轮自动恢复改动。这两个问题需要分别处理：加载修复版本，以及补资源执行与继续调度，不能只调整播放重试次数。

## 迁移依据

上游是仓库已保存的 OCS 5.4.0，提交 1e93399a22b54fac80bb6bae131a4b208b5d8af9，MIT 许可。源码及许可继续保留在 third_party/ocs，生成文件和片段行号由构建清单记录。

原先主要复用了目录识别、iframe 搜索及音视频播放的一部分。本次将 JobRunner.read、readPPTWithAudio、hyperlink 的原方法通过 TypeScript AST 提取到本地可执行脚本，不再只保存上游源码而未调用。其等待函数改接本系统的可取消等待。

计时书籍按原有“等待 → 正文 → 等待 → 封底 → 等待 → 阅读确认”的流程适配到受控步骤，保留真实等待时间。普通书籍在平台提供阅读器末页入口时使用该入口。不会直接改 isPassed、章节完成标记或成绩。

## 资源行为

| 资源或场景 | 新流程 |
| --- | --- |
| 视频和音频 | 保留已播放位置；启动和意外暂停最多尝试 3 次；稳定播放后恢复预算 |
| 文档、PPT | 使用平台原有阅读完成入口，随后重新读取平台进度 |
| 带音频 PPT | 执行上游逐页处理方法，不再只把它当作一段音频 |
| 普通书籍 | 等待阅读器初始化，使用平台提供的页码导航入口 |
| 计时阅读 | 按实际计时和页面阶段推进；人工暂停后保留页码阶段 |
| 链接任务 | 调用上游链接处理方法，并核验平台反馈 |
| 已完成／非任务点 | 明确记录跳过，继续搜索，不重复播放 |
| 同章节多个资源页 | 继续访问下一资源页；记录访问集合，防止反复跳同一页 |
| 坏视频、未知阅读器、控件加载失败 | 记录资源原因，继续其余资源和章节 |
| 明确章节加载错误 | 记录该章节错误，继续下一个可访问章节 |
| 进度读取超时、HTTP 408/429/5xx | 最多重试两次；重试耗尽后保留真实错误 |
| 登录失效、浏览器断开、目录合同变化 | 明确中断，不当作普通资源跳过 |
| 章节或视频练习 | 暂缓该资源，处理其余资源后列入集中介入清单 |
| 身份验证 | 立即等待用户处理，不自动绕过 |

阅读函数返回 handled 只表示“操作已经发出”，不能据此算完成。平台未确认的阅读、视频或章节都保留未完成状态。

## 调度与人工闭环

单资源错误不再直接暂停整门课程。执行器先遍历本章其余资源页，再处理其余未完成章节，最后统一回读目录。仍有未完成项时只发出一次集中介入提示，列出章节、资源和具体原因，并保留浏览器。

点击“处理后继续”会重新核对平台状态并跳过已完成部分。当前介入章节保持原页面，避免重新打开视频而丢失手动播放状态。任务目标集合在本轮保持稳定，暂缓项不加入 completed，也不把跳过当作进度完成。

人工任务暂停、停止、查看器关闭仍是独立事件。长 PPT 的等待可以被暂停打断，播放恢复不能反过来取消用户主动暂停。

运行事件、资源处理、暂缓原因、网络重试和最终汇总写入现有任务日志文件；前台保持简短提示，不新增诊断页面。

## 验证与边界

新增测试覆盖真实浏览器中的文档回调、带音频 PPT、链接、计时阅读、可取消等待、有限资源页遍历，以及服务层的坏资源后继续、跨章节继续、阅读未确认、网络重试和身份验证边界。

本次重点补全学习通资源流程。其他平台仍按已验收的对应适配器工作，不能把这一轮学习通测试解释为其他平台所有阅读器已完成真实验收。随机答题、强制重学、绕过验证和直接伪造完成不属于本次迁移。章节练习仍需要独立、受权限控制的答题流程。

自动回归与真实账号现场验证分别报告。只有新进程的 capabilities 接口返回本文件的引擎标识，才说明修复已经被运行中的后端加载；源码存在不代表当前服务已经更新。
