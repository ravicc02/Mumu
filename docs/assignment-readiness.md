# 作业要求与作答状态

## 三项独立判定

平台提交窗口、页面填写状态和自动处理能力分别记录。

- submittable 表示平台存在有效作答或提交入口，用于筛选仍开放的未交作业。这个字段不表示已经填写，也不表示可以自动完成。
- answer_state 记录 unknown、empty、partial 或 filled。读取题目和控件后，才计算已填写作答单元数量。filled 只表示控件有内容，提交成功仍需原有核验流程确认。
- execution_state 记录 unchecked、direct_fill 或 manual_required。要求提交报告、项目源码、视频、压缩包或设计图的作业进入人工处理。

## 前台显示

未检查的作业显示“待检查”，空白题目显示“待作答”，有部分内容时显示填写数量。材料作业显示“需材料”和具体交付项，其入口为“查看要求”，批量自动执行跳过这些作业。

日期标签显示作答期内、即将截止或已过截止。采集数量统一称为待处理作业，避免把提交入口和完成结果混为一谈。

## 检查与执行

学习通采集时读取题目和原生控件，不点击答案、暂存或提交。现有缓存可通过作业行的检查按钮刷新，也可调用 POST /api/assignments/{id}/inspect。

检查结果随作业存入 assessment_json，后续采集继续更新。自动执行前再次检查实际题目，材料作业在模型调用和填写之前停止。创建、重试、人工继续与自动调度均不能绕过已知材料要求。

规则根据页面可见要求识别材料交付，无法代替文件完整性或内容正确性核验。已有附件也需要用户在原页面检查，系统不会把一段文字当作文件上传完成。
