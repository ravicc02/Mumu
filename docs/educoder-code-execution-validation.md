# 头歌代码实验首轮实现与验收

## 1. 范围

本轮将头歌 Java/JUnit 网页编辑器实验固化为确定的执行流程：读取题目与授权代码文件、模型生成完整文件、检查修改边界、同步编辑器并保存、完整回读、发起评测、识别结果、根据明确的编译或测试失败进行有限修复，最后核验关卡状态和课堂结果。

远程虚拟机、Canvas 内桌面操作不属于本轮。此类环境能够被识别并阻止误写，但尚未实现自主操作。模型角色配置界面和其他编程语言也不属于本次验收。

## 2. 实现约束

- TaskSpec 绑定实验实例、关卡、文件白名单和评测权限。每关最多 4 次模型请求、4 次评测，允许 3 次代码修复。
- 保留 Begin/End 标记及其外部代码。生成前、保存前和保存后检查完整文件，发现其他修改时停止覆盖。
- 使用编辑器粘贴事件同步完整文件，避免逐行输入触发 Monaco 自动缩进。保存接口使用网页编辑器的 tab_type=1。
- 评测票据生成早于计算服务启动。只在平台开始正式查询后跟踪对应票据，避免启动前查询造成错误结论。
- 评测期间不完整的任务快照只允许在有界等待中暂缓处理，不能视为通过。授权刷新使用临时页面，不刷新正在评测的实验页。
- 明确的编译或测试失败才反馈模型修复；服务中断、资源紧张等环境故障单独报告。结果未知时停止自动提交，先查询原评测。
- 完成标准同时要求全部关卡通过和课堂实验结果确认。代码保存、模型自述、截图、单次接口返回都不能替代最终完成证据。

## 5. 自动评测流程与原页续跑修正

日期：2026 年 11 月 13 日。本节记录后续源码修正。第 3、4 节是此前真实测试的历史记录，不表示本节修改已经加载到运行服务。

当天日志显示，保留的代码任务使用了保存后待审核权限，未发起自动评测。人工处理后继续时，执行器又打开实验入口，造成回到初始页面。

当前实现采用以下流程：

1. 读取完整题目和代码文件，包括占位内容、框架及原有注释。
2. 模型返回完整文件，只补齐允许修改的区域。要求代码简洁，不新增注释，保留原有 Begin/End 标记。
3. 检查文件版本、保存、完整回读，再发起评测。
4. 将明确的编译错误、运行异常和测试失败反馈模型，修正后重复评测。每关最多 4 次模型请求和 4 次评测，允许 3 次修复。
5. 当前关卡通过后进入下一关。全部关卡和课堂结果均核验通过，才标记完成。

“头歌自动评测”默认开启，独立于学习通最终提交权限。重试使用当前设置；人工处理后的继续接回原实例、原关卡和当前编辑器代码。继续时记录权限变化，保留审查依据。

已有评测运行时只查询这次结果。结果未知时停止重复提交；平台服务故障单独报告。评测前发现人工代码变化时保留现场，不刷新或覆盖。读取编辑器使用本地复制事件，不读取或修改系统剪贴板。

本次检查了保留浏览器的编辑器读取能力，未保存真实文件、发起真实评测或改变页面地址。隔离测试覆盖当前页续跑、实例校验、人工编辑接回、文件并发变化、完整模板提示词、编译与运行错误修复、待决结果查询及权限默认值。设置界面用隔离响应验证了头歌开关默认开启、学习通开关保持关闭，未保存用户设置。
