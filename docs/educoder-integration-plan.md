# 头歌平台接入方案

调研日期：2026 年 11 月 12 日（Asia/Shanghai）。

文档状态：历史接入设计。初版现已实现，当前状态见[验收记录](educoder-code-execution-validation.md)。本文保留当时的调研依据，课堂及作业标识使用匿名示例。

## 1. 结论与首版范围

可以按用户提出的路径接入：个人主页 → 教学课堂 → 正在进行 → 用户选择课程 → 课堂实验 → 采集未完成实验 → 进入关卡执行 → 核验平台结果。

头歌的课堂实验应接入现有“作业”业务。它不是视频播放任务，不能只在 OCS 平台目录中加一个名称，再交给网课播放器执行。课程选择可以复用现有账号、课程展示方式，执行层需要新增头歌实验适配器。

首版建议先支持本次已看到的网页代码实验，验证 Java/JUnit 的完整流程。复用软件已有的任务状态、独立浏览器、实时操控、日志、诊断导出和任务删除。云桌面、图形仿真、文件交付型实验分别适配，不能在首版直接声明全部支持。

所有接入逻辑运行在本软件内。正常访问头歌自身的服务，并调用用户已配置的模型；不增加 OCS 服务或其他自动化中转服务。

### 2.4 实际路由结构

以下是本次页面验证的路由形式。花括号是文档占位符，不是已实现的本地 API。

~~~text
https://www.educoder.net/users/{user_login}/classrooms?status=processing
https://www.educoder.net/classrooms/{course_route_id}/announcement
https://www.educoder.net/classrooms/{course_route_id}/shixun_homework
https://www.educoder.net/classrooms/{course_route_id}/shixun_homework?tabs=1
https://www.educoder.net/classrooms/{course_route_id}/shixun_homework?tabs=2
https://www.educoder.net/classrooms/{course_route_id}/shixun_homework/{homework_id}/detail?tabs=1
https://www.educoder.net/tasks/{course_route_id}/{homework_id}/{task_identifier}?coursesId={course_route_id}
~~~

本次 tabs=1 对应实验列表的“提交中”，tabs=2 对应“补交中”。这不是完成状态编码，更不能据此猜测接口内部枚举。

实际进入的软件工程课堂路由标识为 CLASSROOM_A，实验详情里的一个返回链接则使用 100001。需要在成功接口响应中核对课堂别名与内部 ID 的关系，不能把路由代码和数字编号当成两门不同的课程。

本次打开的 JUnit 入门实验 homework_id 为 1234567。执行地址中的 task_identifier 来自平台跳转，属于当前用户的实验实例，不能替代稳定的作业 ID，也不能复制给其他账号。

## 3. 产品流程

~~~text
平台 → 头歌 → 添加账号 / 授权
                   ↓
             获取正在进行的课堂
                   ↓
             用户选择一个或多个课堂
                   ↓
作业 → 头歌账号 → 所选课程 → 采集课堂实验
                   ↓
        未完成 + 当前允许提交 → 待执行
                   ↓
        读取关卡 → 编辑与保存 → 用户审核或评测
                   ↓
             平台核验 → 任务结果与诊断
~~~

“平台”继续承担平台选择、授权和授权记录；“作业”承担课程选择、实验列表和执行。首版无需增加一个含义相同的侧栏入口，也不把头歌实验放入视频“网课”执行器。

用户只授权账号，不代表自动执行所有课程。课程选择需要持久化；手动采集和以后的定时采集都限定在所选课程内。初次采集只列出实验，不自动打开所有实验环境。

## 4. 授权与请求方式

### 4.1 本地 Chrome 登录态与软件账号

本次能在 Chrome 中访问头歌，不代表软件新建的任务 Profile 已有头歌授权。现有软件为每个任务创建独立 Profile，不能直接占用正在使用的个人 Chrome 目录。

正式接入建议提供受控的头歌授权流程：保存必要 Cookie 与站点存储，再在软件管理的浏览器中验证“当前用户身份 + 可访问的课堂列表”。如果实现“导入当前 Chrome 授权”，应由本地扩展或明确的会话桥接完成，只导入头歌所需的站点数据；不要复制整个个人 Profile 或尝试绕过 Chrome 的密钥保护。

授权记录只在上述核验通过后标为就绪。仅仅看到头像、首页能打开，或者 Cookie 文件非空，都不足以确认后续采集和实验执行可用。授权失效时回到原账号刷新授权，不创建一个看似成功的新账号。

### 4.2 现网请求不是只有 Cookie

在当前页面公开加载的前端脚本中，已发现以下请求头名称：

- Pc-Authorization，代码中与 _educoder_session Cookie 关联。
- X-EDU-Type。
- X-EDU-Timestamp。
- X-EDU-Signature。
- Origin 等来源上下文。

这说明“导出 Cookie 后直接用裸 HTTP 请求全部接口”的方案尚未成立。不能把签名值、时间戳或会话值写死在程序里。

实施时应先通过获授权账号的一次正常请求，核对请求头、参数、分页、权限与响应结构；再决定哪些读接口可以使用本地 HTTP 客户端。未复验前，浏览器上下文是授权与页面行为的基准。正式方案不依赖这次调研工具的 Chrome 扩展连接。

登录、身份校验、课程采集、实验启动和评测必须分别验证。首版不宣称所有链路已经实现无浏览器接口化。

### 4.3 从现网公开脚本发现的接口

下表均为“源码已核对”，没有在本次调研中用用户凭据直接调用。参数名、完整响应字段、状态枚举和权限仍需在开发阶段复验。

| 方法与路径 | 源码中的用途线索 | 接入时的核验重点 |
| --- | --- | --- |
| GET /api/users/get_user_info.json | 获取用户信息 | 当前用户标识、登录有效性、学生身份 |
| GET /api/users/{username}/courses.json | 用户课堂列表 | 与页面“我学习的、正在进行”的参数对应；翻页和总数 |
| GET /api/courses/{id}/top_banner.json | 课堂顶部信息 | 内部 ID、路由代码、课堂名称和权限 |
| GET /api/courses/{id}/left_banner.json | 课堂侧栏信息 | 课堂实验模块及目录分类 |
| GET /api/courses/{id}/homework_commons.json | 作业列表 | 只采课堂实验的类型参数；个人完成进度及提交窗口 |
| GET /api/courses/{id}/homework_commons/list.json | 另一种列表调用 | 与上一接口的场景差异，不能默认二者可互换 |
| GET /api/homework_commons/{id}.json | 作业详情 | 说明、关卡配置、当前用户可见字段 |
| POST /api/homework_commons/{id}/works_list.json | 作品列表 | 是否适用于学生当前用户；不能假设可读取全班作品 |
| GET /api/shixuns/{id}/shixun_exec.json | 启动实验 | 获取个人实例及跳转；这是启动行为，不当成普通只读查询 |

公开脚本还出现了 POST 形式的 statistics.json。不能根据路径叫“列表”或“统计”就猜 HTTP 方法，也不能因为请求是 GET 就认为没有副作用。

代码文件读写、保存回执、关卡切换、评测提交和评测结果轮询接口，尚未完成现网请求复验。本方案不编造这些接口地址或响应字段。

## 5. 课程与实验采集

### 5.1 课程采集

1. 校验当前账号身份，进入个人教学课堂。
2. 选择“正在进行”，获取课程列表和分页信息。
3. 记录课堂路由标识、内部 ID、标题、当前角色、所属班级和课堂状态。
4. 用户选择要处理的课程，保存选择范围。
5. 后续采集按所选课程执行；课程无权限或已结束时，保留原因并停止该课程采集。

本次个人课堂列表为 15 条/页，实验列表为 20 条/页。实现必须处理分页、目录分类和去重，不能只读取首屏。也不能将课堂卡片上的某个图标计数直接解释为实验总数。

头歌课堂的“正在进行”与本项目此前的“2026 开课”不是同一条件。首版以用户选择和课堂状态为准，不根据课程名称猜开课年份，更不能让固定学年过滤把已选课堂的实验全部隐藏。

### 5.2 实验采集

进入所选课堂的“课堂实验”，读取全部可见目录和完整分页，再建立两组信息：

- 个人完成情况：总关卡、通过关卡、未评测关卡、评测失败关卡。
- 开放情况：未开始、提交中、补交中、已截止、已归档，以及班级对应的起止时间。

数据库课堂实际存在“实验一、实验二、测验、未分配目录”等分类。需要确认“全部”是否已包含这些目录；如果遍历分类，必须用稳定的实验 ID 去重。

课程发生网络错误或只采到部分分页时，不能清空该课程以前的作业。失活标记只能在同一账号、同一课程、同一来源范围的完整采集成功后执行，不能误删其他课程的数据。

### 5.3 未完成与可执行判定

建议使用独立字段表达，以下为本地规范化设计，不是已验证的头歌原始响应字段：

~~~text
completion_state: unknown | not_started | partial | passed
availability: unknown | not_open | open | late_open | closed | archived
execution_ready: true | false
blocked_reason: 面向用户的简要原因
~~~

默认待执行条件为：未完成、当前允许提交、有访问权限、执行类型受支持，并且本地没有同一实验的活动任务。只有“提交中”或“补交中”仍不够，还需排除已通过的实验。

| 个人状态 | 提交窗口 | 默认结果 |
| --- | --- | --- |
| 0/4 或部分通过 | 提交中 / 当前允许补交 | 待执行 |
| 全部关卡已通过，课堂结果已核验 | 任意 | 已完成，跳过 |
| 未完成 | 已截止 / 已归档 | 显示为历史未完成，禁止自动执行 |
| 未完成 | 未开始 | 等待开放 |
| 状态或权限无法核实 | 未知 | 待确认，不能伪装成可提交 |

分班截止时间和补交权限优先按当前账号适用的配置核验。日期比较需明确时区并考虑服务端时间，不能只解析一段没有时区的展示文字。

## 6. 数据模型与稳定标识

建议复用 accounts、assignments、jobs、job_events、artifacts 和现有诊断存储。课程发现与选择增加通用平台课程记录，不把课堂实验伪装成 learning_runs 中的视频播放任务。

| 对象 | 建议保存的信息 |
| --- | --- |
| 平台账号 | platform=educoder、授权状态、必要站点存储、最近核验结果 |
| 平台课程 | 上游内部 ID、路由别名、名称、角色、所属班级、课堂状态、采集时间 |
| 课程选择 | account_id、course_id、source_kind=shixun_homework、是否启用 |
| 实验作业 | homework_id、course_id、来源类型、开放窗口、总关卡和已通过数、当前完成状态 |
| 实验实例 | 当前账号的 task_identifier / 实例 ID、关卡 ID、运行环境类型、最近保存与评测回执 |
| 执行尝试 | 继续使用现有任务 ID、attempt、parent_job_id、阶段、进度与结果 |

作业去重建议按“平台 + 账号 + 课堂 + homework_id”。标题可以重名，个人任务地址也可能变化，二者均不能作为唯一键。路由代码的大小写要保留。

关卡 ID、原始页面地址、目录分类、运行环境和完成依据可放入平台扩展元数据；字段需经接口复验后定型。头歌无开课年份时保存明确的未指定值，并调整查询语义，不能悄悄填一个年份冒充真实数据。

任务删除继续沿用现有逻辑：移除本地执行列表，不删除平台实验，不清除维护证据，也不取消已完成核验后的重复执行保护。

## 7. 实验执行器

### 7.1 独立执行链路

~~~text
准备任务浏览器
→ 核验账号与课程
→ 打开实验详情
→ 获取当前用户实验实例并接管新标签页
→ 等待代码环境就绪
→ 读取全部关卡状态
→ 选择未通过关卡
→ 读取任务要求、文件树与完整代码
→ 生成最小修改并写入
→ 确认保存
→ 按当前模式等待审核或启动评测
→ 等待评测结果
→ 核验关卡通过
→ 继续下一未完成关卡
→ 复验课堂实验整体结果
~~~

每一步输出实际动作和证据。不能把“模型已经生成代码”“编辑器已有内容”“页面已经打开”当成完成。

### 7.2 代码编辑与保存

本次已确认 JUnit 实验使用 Monaco 编辑器，页面可读到任务说明和代码。Monaco 的 DOM 文本与输入 textarea 不保证包含完整文件，实现不能仅靠读取当前可见行就覆盖整份代码。

需要核实完整文件内容、当前文件路径、只读范围和编辑器模型的获取方式。修改时保留原有 package、import、类名和实验脚手架，只改任务要求允许的区域；对缺少依赖或文件的情况返回具体问题。

保存需要平台回执或重新读取后的内容一致性证据。页面没有通用“暂时保存”按钮时，应适配头歌自己的保存机制，不能盲目寻找学习通的按钮。仅按 Ctrl+S 或看见编辑器文本变化，不足以声称已保存。

### 7.3 自测与评测

页面确实有“自测运行”和“评测”，但本次没有点击它们，尚不能证明自测完全不计分或不产生远端执行记录。

首版应把评测视为可能记录成绩与进度的提交行为。关闭自动提交时，在代码已保存后进入待介入，由用户审核并决定是否评测；开启自动提交后，按明确的任务授权进行评测和核验。

是否必须评测通过才能解锁下一关，还需按实验类型验证。如果平台要求先过关，关闭自动评测时就停在当前关等待审核，不能声称整项实验已准备完成。界面应明确显示“当前关卡已保存，等待评测”，并保留尚未处理的关卡数。

模型修改、保存、自测和评测是不同阶段。评测通过后，才将该关卡记为通过。失败时返回编译错误、测试失败或环境故障的区别；不通过无限重复点击评测来掩盖问题。

“下一关”按钮和当前关卡高亮不能单独作为完成证据。本次页面初始状态曾出现带 null 的下一关地址，关卡目录里的图标也不足以区分未评测与已通过。执行器应等待有效的关卡标识和明确状态，不拼接或访问占位地址。

### 7.4 重试、暂停与继续

- 用户暂停后，不再编辑下一文件或提交下一次评测；已发到服务器的评测可能仍会继续，恢复时先查询该次结果。
- 网络超时后先核对上一次保存或评测是否成功，不能直接重复提交。
- 继续任务复用本次保留的实例和页面；重试先读取平台已通过关卡，跳过已完成部分。
- 到达单关重试上限时输出失败依据；用户补充材料或修改后再继续。
- 需要云桌面、图形操作、报告文件或不支持的环境时，明确进入对应处理分支，不伪装成普通问答题已完成。

### 7.5 浏览器与远端资源隔离

继续复用现有“一任务一 Profile、一控制连接、一实时通道”的隔离规则。查看页关闭只断开画面，后台任务继续；执行浏览器真正退出或失联才记录中断。

本地浏览器隔离不等于头歌远端实验环境隔离。相同账号在不同课堂遇到相同实践项目时，可能指向同一远端实例或仓库；需要在开发中验证。首版宜限制同账号的实验执行并发，并在取得上游实例标识后按远端资源加锁，避免两个任务互相覆盖代码。不同账号和软件其他业务不应被一个全局锁冻结。

## 8. 状态机与完成依据

沿用用户已确定的任务颜色和语义，新增实验阶段，不另造一套相互矛盾的顶层任务状态。

| 状态 | 头歌实验中的进入条件 | 用户可做的事 |
| --- | --- | --- |
| 排队中 / 运行中 | 准备环境、读取关卡、编辑、保存或等待已提交评测 | 查看、暂停、停止 |
| 已暂停，灰色 | 用户主动点击暂停 | 继续或停止 |
| 中断，红色 | 模型、网络、平台服务或执行浏览器异常，无法继续确认结果 | 查看原因、核对上次评测、重试 |
| 未完成，红色 | 关卡未通过、素材缺失、格式或环境未支持、重试上限到达 | 补充材料、人工操作或重试 |
| 待介入，黄色 | 所需修改已保存，未开启自动评测 / 提交，等待用户审核 | 查看修改、评测或继续处理 |
| 已完成，绿色 | 所有关卡通过，课堂实验的个人结果也已核验 | 查看结果，跳过重复执行 |
| 停止中 / 已停止 | 用户请求停止并完成资源收尾 | 保留记录，后续重新执行 |

建议阶段包括 opening_experiment、environment_starting、reading_challenges、editing_code、saving_code、evaluating、verifying_challenge 和 verifying_assignment。它们描述任务正在做什么，不替代顶层状态。

当前 jobs 的已完成状态还要求 submitted_verified。头歌适配器应在“全部关卡通过 + 课堂结果回读确认”后输出该标准化结果；不能直接根据编辑器内容填充该字段。若自动提交关闭，则保持待审核；如果评测结果未知，应保留未知提交状态，拦截盲目重试。

整体进度以真实关卡为单位。4 个关卡通过 2 个时显示 2/4；正在生成代码不算通过。环境启动、模型思考等阶段显示阶段反馈，不能提前灌入完成百分比。

## 11. 用户界面与诊断输出

### 11.1 前台展示

作业页按“账号 → 课程 → 实验”组织；每项显示名称、开放状态、已通过 / 总关卡、截止时间和执行入口。已完成与已截止可切换查看，默认突出可执行未完成项。

任务详情显示当前关卡、文件、动作、评测进度及结果。用户看到的是“第 2 关编译失败，需修正后重试”等简要信息；完整错误、请求元数据和调用栈进入诊断包，不在卡片上倾倒长 URL。

“保存代码”“自测”“评测”“课堂结果核验”分别显示。没有明确保存回执时不得显示已保存；没有平台确认时不得显示绿色完成。

### 11.2 后台可维护日志

建议沿用现有诊断包，记录如下平台事件：

~~~text
educoder.auth_verified
educoder.courses_collected
educoder.experiments_collected
educoder.experiment_opened
educoder.environment_ready
educoder.challenge_read
educoder.code_saved
educoder.evaluation_started
educoder.evaluation_result
educoder.assignment_verified
educoder.intervention_required
~~~

每条事件关联本地任务 ID、尝试次数、课程和实验 ID、关卡 ID、执行器版本、耗时、错误分类、上一次动作及后续建议。保存和评测需记录相应回执标识或内容摘要，以便区分“未发出”“已发出但超时”“平台已确认”。

诊断包默认不包含 Cookie、Pc-Authorization、完整签名、个人敏感资料或带凭据的 WebSocket 地址。代码内容和页面截图遵循现有显式导出选项；默认以文件路径、差异摘要和哈希辅助定位。请求响应只保留解决问题所需的字段，并进行脱敏。

平台页面与模型返回的内容均作为数据处理，不赋予它们关闭其他任务、导出其他账号凭据等权限。

## 12. 实施顺序与验收

### 12.1 阶段划分

| 阶段 | 交付内容 | 通过条件 |
| --- | --- | --- |
| A：采集闭环 | 头歌平台、授权验证、正在进行课堂、用户选课、课堂实验列表 | 与真实页面逐项比对，完整分页；已完成和已截止不被当成可执行 |
| B：代码实验闭环 | 网页代码环境、关卡读取、修改保存、评测和整体核验 | 在单独授权的测试实验中从未评测到平台确认完成；不能拿本次只读浏览当验收 |
| C：用户流程与维护 | 人工审核、继续、重试、后台运行、实时操控、诊断导出、定时采集 | 关闭查看端不影响执行；失败可仅凭诊断包定位阶段和原因 |
| D：扩展实验类型 | SQL、云桌面、终端、报告和图形环境 | 各类型分别验证并开放能力，不用一种环境的成功覆盖其他类型 |

优先做到 A 和 B，证明用户指定路径真正闭环，再扩展更复杂的实验环境。

### 12.2 必测用例

| 用例 | 预期结果 |
| --- | --- |
| 两个账号使用同名课堂或实验 | 分别采集，不串账号与代码 |
| 课堂进行中，但实验已截止 | 不进入自动执行队列 |
| 实验尚未完成，但仅允许补交 | 校验当前班级补交权限后才允许执行 |
| 实验已通过，列表中仍有查看或学习按钮 | 跳过，不重复启动或评测 |
| 超过一页的课程和实验 | 全部分页读取、去重；失败不抹掉其他范围的数据 |
| 同一课堂同时出现代码和数字路由标识 | 对齐映射，不建立重复课堂 |
| 同一实验重复点击执行 | 只产生一个活动任务 |
| 两个课堂可能共享同一远端实验实例 | 远端资源互斥，避免覆盖 |
| 浏览器登录失效或签名错误 | 明确授权 / 请求异常，不显示采集成功或空作业 |
| 开启挑战打开新标签页 | 实时画面与控制切到正确执行页 |
| 编辑器仅渲染部分代码 | 读取完整文件，不能截断覆盖 |
| 代码已输入但保存失败 | 不显示已保存，不进入自动评测 |
| 提交评测后客户端超时 | 核对已有评测，不盲目重复提交 |
| 四关中两关已通过 | 跳过已通过关卡，进度保持 2/4 |
| 全部关卡通过，但课堂结果尚未更新 | 继续核验，不能立即标绿色完成 |
| 未开启自动提交 | 保存后待介入，不自动点击评测 |
| 人工暂停 / 关闭查看页 / 执行进程退出 | 分别为暂停 / 继续运行 / 中断 |
| 导出其他测试者的失败日志 | 无凭据泄漏，能定位课程、实验、关卡与失败阶段 |
