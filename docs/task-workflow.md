# 任务流程与状态约束

## 任务状态

| 状态 | 显示 | 进入条件 | 下一步 |
| --- | --- | --- | --- |
| `queued` | 排队中 | 已创建，正在准备任务专属浏览器 | 暂停、停止，或等待分配 |
| `running` | 运行中 | 已启动任务专属执行器 | 暂停、停止，或等待结果 |
| `paused` | 已暂停，灰色 | 用户主动暂停 | 继续或停止 |
| `stopping` | 停止中 | 已接收停止请求，正在退出 | 等待释放资源；超时强制取消 |
| `stopped` | 已停止，灰色 | 用户停止完成 | 核对结果后重试 |
| `interrupted` | 中断，红色 | 模型、上游、网络、浏览器或服务异常 | 查看原因，必要时核对提交，再重试 |
| `incomplete` | 未完成，红色 | 未完成填写、素材缺失、格式不支持或未确认提交 | 原窗口人工处理后继续，或重试 |
| `needs_intervention` | 待介入，黄色 | 已填写完成，尚未确认提交 | 审核、手动提交、确认提交，或关闭浏览器 |
| `completed` | 已完成，绿色 | 已完成且 `submission_status=submitted_verified` | 查看结果，不再重复执行 |

旧数据中的 `failed` 仍可读取，界面归入异常；新执行优先按原因区分中断与未完成。

## 状态转换

```text
创建 -> 排队 -> 运行 -> 已完成（已确认提交）
                  -> 待介入 -> 人工确认提交 -> 已完成
                  -> 未完成 -> 人工处理后继续 -> 运行
                  -> 中断 -> 核对上次结果 -> 重试（新任务）
排队 / 运行 -> 已暂停 -> 继续（回到原阶段）
排队 / 运行 / 已暂停 -> 停止中 -> 已停止
```

- 状态转换在 SQLite `BEGIN IMMEDIATE` 事务中验证，停止与完成竞态只有一个结果可生效。
- 仅填写完成、模型自报成功、通知发送成功都不能作为绿色完成的依据。
- 填写后默认自动点击“暂时保存”，核对平台成功回调或新出现的保存成功提示。暂存失败不会进入待审核，会记录原因并保留原浏览器；暂存不等于最终提交。
- 自动提交必须核验匹配当前作业的提交结果页。人工点击“我已提交”记录人工确认。
- “确认已核对”确认填写内容，任务继续保持黄色；“确认未提交”允许重新处理作业。
- 任务提交状态未知或仅有未经核验的提交声明时，所有执行入口均先要求核对，不能直接重试。
- 已确认提交的作业不能降级为未提交，也不能通过历史尝试再次执行。

## 账号与浏览器资源

同一账号的不同作业和网课可以并行运行。每个任务有专属 Chrome 数据目录、控制连接和实时画面。同一个作业或课程仍禁止重复启动。

授权、采集和任务执行相互检查账号占用。授权前先关闭旧预览；采集期间禁止启动授权、交互浏览器和新任务。用户会收到具体冲突原因。

待审核和未完成任务可以保留原 Chrome、BrowserSession 与任务目录。保留窗口只属于当前任务，不阻塞其他作业或网课。关闭窗口仅释放该任务资源。

| 操作 | 浏览器与结果变化 |
| --- | --- |
| 进入实时浏览器 | 将当前任务的同一窗口切到前台，Agent 继续执行 |
| 人工处理后继续 | 仅用于有保留窗口的未完成任务；继续当前页面，保留已有答案 |
| 关闭浏览器 | 关闭保留会话并释放锁，任务结果保持不变 |
| 我已提交 | 确认提交结果、标记完成、释放会话；释放失败时保留关闭入口 |
| 重试 | 关闭该任务旧会话，创建新尝试并保留历史关系 |
| 服务重启 | 执行中的任务标记中断；审核和未完成结果保留，旧浏览器不再冒充可续接 |

人工与 Agent 使用同一页面。修改正在操作的控件时仍可能互相覆盖，需要独占操作时先暂停任务。

## 交互反馈与实时日志

- 面板按账号和作业聚合，详情弹窗保留全部尝试记录。
- 按钮使用后端 `actions`，操作只锁住相应任务；其他账号、导航和日志仍可使用。
- 排队显示位置与占用者；运行显示阶段、心跳、已处理单元与当前页面；结束显示原因、最后动作和处理建议。
- 结构化填写在单元边界暂停；进行中的模型请求可返回，但暂停后不会继续写入下一单元。停止会取消进行中的受控操作。
- WebSocket 断线按事件 ID 续传、去重；过慢客户端收到重载标记。重连同时刷新状态和凭证。
- 切换账号时丢弃过期异步结果，防止登录、采集结果、截图或日志串到另一个账号。
- 采集状态、在途请求与进度轮询按账号管理。不同账号可以同时采集，一个账号结束不会停止另一个账号的轮询；同一账号仍禁止重复采集。
- PC 窄屏将日志移到浏览器下方，宽屏并排显示；浏览器可展开，日志可收起或导出。
- 最终截图直接按页面坐标分段截取，每段不超过 1000 CSS 像素并保留 64 像素重叠；截图过程不滚动当前页面。详情支持逐段翻页和放大，旧长图在客户端按相同规则显示。

## 删除任务

面板表头统一为“任务”。每行右侧的“...”菜单提供查看和删除入口，作业与网课使用相同操作。删除前确认任务名称及所属账号。

删除按账号和作业或课程聚合，同一项任务的全部历史尝试一并移出列表。刷新页面不会重新显示旧尝试；后续新建任务使用新的执行记录。任务计数、分页和沐沐的本轮统计同步更新。

运行、排队、暂停、停止中以及仍保留浏览器的任务禁止删除。用户先停止任务或关闭保留的浏览器，服务端再校验整组尝试，防止从旧记录绕过限制。

删除使用 `deleted_at` 标记。维护日志、执行证据与提交核验记录保留，平台上的作业、课程、授权和已保存进度不受影响。已确认提交或提交状态未知的作业仍受原有执行保护约束。

## 接口

微信连接器通过 `GET /api/connectors/weixin` 读取绑定状态与推送设置；该接口不申请二维码，也不返回绑定密钥。`PATCH /api/connectors/weixin/preferences` 独立更新 `new_assignments_enabled` 与 `completion_enabled`。

新增作业推送默认关闭，完成推送保留默认开启。新增提醒仅由定时采集触发，手动采集更新基线但不发送新增提醒。提醒按账号、学年和作业 ID 去重，失败后保留待发送记录，仅在下次成功核验该作业仍可提交时重试；通知失败不改变采集结果。完成开关在任务结果产生时读取，关闭后不发送该任务结果通知。

| 路径 | 用途 |
| --- | --- |
| `POST /api/jobs` | 创建任务，校验授权、模型配置、作业与提交状态 |
| `GET /api/jobs`、`GET /api/jobs/{id}` | 状态、阶段、进度、可用操作和占用关系 |
| `DELETE /api/jobs/{id}` | 移除当前账号这项作业的全部任务尝试 |
| `DELETE /api/learning/runs/{id}` | 移除当前账号这门课程的全部任务尝试 |
| `POST /api/jobs/{id}/pause`、`resume`、`stop` | 暂停、恢复与停止 |
| `POST /api/jobs/{id}/continue` | 接回未完成任务的原浏览器 |
| `POST /api/jobs/{id}/retry` | 创建新尝试；可传当前确认的 `auto_submit` |
| `POST /api/jobs/{id}/finish-intervention` | 关闭保留浏览器并释放资源 |
| `POST /api/jobs/{id}/submission-status` | 人工核对填写或提交结果 |
| `GET /api/jobs/{id}/events` | 持久化事件，支持 `after_id` |
| `WS /ws/jobs/{id}?after_id=...` | 实时事件与断线续传 |

## 验证范围

后端回归测试覆盖创建、重复任务拦截、暂停与恢复、停止取消、重试、同窗口续接、人工审核、确认提交、资源释放、队列占用、状态竞态和授权及采集互斥。浏览器与模型在这些测试中使用替身，不产生真实作业提交。

前端测试覆盖过期响应、事件去重、服务端操作权限、阶段状态、重试提交模式和组件动效的收敛性。页面验证覆盖实际本地数据的任务聚合、详情、账号切换、筛选多选、菜单关闭与浏览器展开。

本轮未重新执行真实模型答题与远端提交；测试通过不能替代目标平台的真实提交验收。Windows 安装包需重新构建后才包含这些改动。

2026 年 11 月 11 日，使用获授权的 gym 测试作业验证了真实平台暂存：收到平台成功回调，刷新后 71 个答案字段保持一致；生成 23 张分段截图。该验证未点击最终提交。
